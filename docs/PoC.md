# PoC スコープ

> 目的: **PostGIS の空間処理が成立するか**を最短で検証する。
> 画面・APIサーバー・ゲーム進行ロジックは作らない。データ取得 → 投入 → 空間クエリまで。

---

## ゴール
1. Overpass API から対象オブジェクト（神社）を取得し、PostGIS に格納できる。
2. 任意の3点（凸包）の内側にあるオブジェクトを **空間SQLで全件SELECTできる**（COUNTはその応用）。
3. 東京都内の現実的な座標で試し、**ゲームとして成立する数のオブジェクトが取れるか**の感覚を得る。

---

## スコープに含む

### データ取得
- Overpass API で神社（`amenity=place_of_worship` かつ `religion=shinto` 相当）を取得。
- 対象エリアは検証用に東京都内の一定範囲（bbox）に限定してよい。

### DB
- ローカルに PostgreSQL + PostGIS を立てる。
- `game_object` テーブルを作成（`id`, `object_type`, `name`, `geom(Point,4326)`、GiSTインデックス）。
- 取得データを INSERT する。

### 空間クエリ（本PoCの主目的）
- 入力した3点から凸包を作り、その内側のオブジェクトを SELECT するクエリを書く。
  - `ST_ConvexHull` で多角形生成。
  - `ST_Contains` / `ST_Within` で内包判定。
  - 面積は `ST_Area(geography)` で実 m² を取得し、感覚を掴む。
- まずは「内側のオブジェクトを全部SELECT」を作る（COUNTはこれを `count(*)` でラップするだけ）。

### 開発用エンドポイント（任意・あると便利）
- 画面は不要。**3点の座標を渡すと、その凸包内のオブジェクト一覧（または件数）と面積を返す**デバッグ用エンドポイント。
- 東京都内の様々な3点でゲーム成立性（神社が何個入るか）を素早く試すために使う。

---

## スコープに含まない
- フロントエンド（地図・GPS・UI）一切。
- ゲーム進行（参加・状態管理・確定・ポーリング）。
- 認証・CORS・ホスティング。
- 神社以外のオブジェクト種別（PoC通過後に拡張）。
- pbf + osm2pgsql による全データ投入（必要になってから）。

---

## 進め方（想定手順）
1. ローカルに PostgreSQL + PostGIS を起動。
2. `game_object` テーブルとインデックスを作成。
3. Overpass API を叩いて神社データを取得（東京エリアの bbox）。
4. 取得結果を `game_object` に INSERT。
5. 任意の3点を入力に、凸包内オブジェクトを SELECT する空間クエリを書いて実行。
6. 面積（`ST_Area(geography)`）も併せて確認し、ゲーム成立性の感覚を掴む。
7. （任意）5〜6 をデバッグ用エンドポイント化して、複数の3点で素早く試す。

---

## 完了条件
- 東京都内の任意の3点で「凸包内の神社一覧・件数・面積」が即座に得られる。
- これにより、面積プリセットの妥当な実値（small/medium/large）の当たりがつく。
