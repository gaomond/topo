# topoの公開準備

初めて作品を見る人が、何を楽しむゲームなのかを理解し、自分で試せる状態にする。READMEは作品と実装を知る入口とし、操作に必要な説明はプロダクト内にも用意する。

この文書は公開準備の作業メモであり、機能の確定仕様は各ユーザーストーリーで管理する。待機画面の目的説明・図とウォークスルーは[US-19](story/19.md)に従う。READMEはUS-14（結果表示）まで完成した公開版を前提に書く。設計判断の節は別途作成する作業とし、公開時の実装と動作確認結果に合わせて仕上げる。公開準備のToDoはこの文書で管理し、READMEには利用上の制約を記載する。

## 1. 作品で伝えること

コンセプトは、小学生のころに学区を少し越えて探検し、知らなかった公園や雰囲気のある神社、お墓を見つけたときのワクワクを再現すること。「あの坂道を越えた先にも、街が広がっている」と感じる未知への探索と、「いつもの街のこの場所に、こんなのがあったんだ」と気づく身近な街の再発見の、両方を目指す。再発見の体験は、特定の種類の場所や集計結果の数に限定しない。

技術的な動機は、位置情報システムへの興味と、R-treeのような空間インデックスを使ってみたいという関心。READMEには動機を記載し、索引の仕組み・利用状況・性能の評価は、後日作成する設計判断と検証結果で説明する。興味を持った技術と、実装・検証できたことを区別する。

### 目的の伝え方

README冒頭はコンセプトとゲームの概要を伝え、その後に「0.5 km²以内に、できるだけ多くの神社を囲む」というお題の例で説明する。数値は現行プリセットから選んだ例で、ゲームの面積設定を変更するものではない。

プロダクト内では、待機画面に目的・面積上限・囲み方の模式図を載せ、プレイ画面のウォークスルーで目的と操作を案内する。表示内容・タイミング・初回記録の確定仕様は[US-19](story/19.md)を参照する。

READMEの遊び方は5段階の短い一覧を維持する。画像を使うかはTBDとし、プロダクトのUIを整えた後に判断する。画像を追加する場合は、一覧との重複を避け、位置・囲む範囲・面積がどう関係するかを補うものを検討する。
