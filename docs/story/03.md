# 01-spec: ゲーム設定の取得（GET /api/config）

## ユーザーストーリー

プレイヤー（クライアント）として、ゲーム作成画面で選べる **対象オブジェクト種別** と **面積プリセット** の一覧を取得したい。ゲーム作成フォームの選択肢を埋めるため。

## 仕様

- エンドポイント: `GET /api/config`
- 認証なし。副作用なし（読み取りのみ）。
- 設定値は静的（DB / PostGIS を使わない）。MVP では定数として持つ。
- レスポンス（`application/json`）:

```json
{
  "objectTypes": ["shrine"],
  "areaPresets": [
    { "key": "small",  "label": "お手軽",   "sqm": 500000 },
    { "key": "medium", "label": "ふつう",   "sqm": 2000000 },
    { "key": "large",  "label": "がっつり", "sqm": 10000000 }
  ]
}
```

- `objectTypes`: 集計対象として選べるオブジェクト種別。MVP は `shrine` のみ。
- `areaPresets`: 面積プリセット。順序保証（small → medium → large）。`key` は `areaPreset`、`sqm` は `areaThreshold` の実値（m²）。

## 受け入れ条件

- [ ] `GET /api/config` が HTTP 200 と上記 JSON 構造を返す。
- [ ] `areaPresets` は small / medium / large の順に 3 件。`sqm` がそれぞれ 500000 / 2000000 / 10000000。
- [ ] `objectTypes` は `["shrine"]`。
- [ ] レスポンスの Content-Type が `application/json`。

## 設計

### パッケージ構成

```
src/main/kotlin/.../topo/
  domain/
    model/          ← AreaPreset, ObjectType（値オブジェクト／定数定義）
  adapter/
    web/            ← ConfigController（@RestController）
  config/
    constants       ← プリセット一覧等の定数定義（必要に応じて）
```

- UseCase 層は設けない。Controller が Domain 定数を直接 DTO に詰めて返す。
  - 理由: DB アクセスもビジネスロジックもなく、定数を右から左に流すだけのため。
  - UseCase 層は次のチケット（POST /api/games 等）で導入する。

### 判断ログ（3 Amigos）

| 論点 | 判断 | 理由 |
|---|---|---|
| 追加要件（regularityThreshold）を含めるか | 含めない | 元 MVP を先に組み切る方針。別チケットで対応。 |
| playerCountDefault を config に含めるか | 含めない | 平面多角形の最小頂点数 3 はジオメトリの自明な制約であり、アプリ設定ではない。 |
| UseCase 層を設けるか | 設けない | DB アクセス・ビジネスロジックなし。シンプルに寄せる。 |
| areaPresets の順序保証 | 保証する（List） | クライアントがそのまま表示順として使えるようにする。 |

## テスト観点

- **Domain（Level 1）**: 面積プリセットの定義（key・label・sqm）が仕様どおりであることを純粋 Kotlin で検証。順序も検証対象。
- **Adapter（Level 2, `@WebMvcTest`）**: `GET /api/config` が 200 と JSON フィールド（objectTypes・areaPresets[].key/label/sqm）を返す。順序・Content-Type を含む。

## スコープ

### 含む

- `GET /api/config` の Controller → Domain 定数 → DTO の縦串実装。
- 面積プリセット・対象種別の定数定義（ユビキタス言語に沿った命名）。
- プロジェクトのパッケージ構成の先例確立。

### 含まない

- UseCase 層の導入（次チケット以降）。
- ゲーム作成・参加・確定・集計などの他 API。
- DB / PostGIS / Flyway へのアクセス。
- 対象種別の動的拡張（shrine 以外）。
- フロントエンド（フォーム実装）。
- CORS 設定。
- 共通エラーレスポンス（`@ControllerAdvice`）の導入。
- 正多角形制約関連（追加要件ドキュメントで管理）。
