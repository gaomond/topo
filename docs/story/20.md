# 01-spec.md — US-20: 確定位置を反映した現在面積と上限超過の警告

実装・検証・独立レビュー承認済み（2026-11-10）。

> プレイヤーとして、確定位置を反映した現在面積と、確定可否を誤解しない警告を見たい。確定後の移動に面積が左右されず、上限に対する配置を正しく判断するため。
> 本仕様は1実装単位（US-20）分。実装と検証を完了した。

プレイ中の面積と凸包は、状態取得APIが返す `currentArea` を画面に表示している。現在の計算は確定済みプレイヤーにもライブ座標を使うため、確定後に移動すると面積が変わってしまう。また、現在面積の超過だけで「このままでは確定できません」と表示しており、確定操作の判定対象との違いが伝わらない。

US-20では、このプレイ中の計算入力を変更し、警告を「上限超過」と超過分の表示にする。

```text
プレイ中のGET → 各プレイヤーから1点を選ぶ
  確定済み: 保存済み確定座標／未確定: ライブ座標
  → サーバーのPostGISで凸包と測地面積を計算
  → currentAreaとして返却 → 地図と面積メーターに表示
```

## 1. 合意された仕様

### 1.1 現在面積に使う位置

| プレイヤーの状態 | 採用する点 |
| --- | --- |
| 確定済み | `fixed_geom` に保存された確定座標。ライブ座標は採用しない |
| 未確定・ライブ座標あり | 最新のライブ座標 |
| 未確定・ライブ座標なし | 計算対象から除外する |

- 1人につき1点とする。確定済みの固定点とライブ点を両方投入したり、座標の重複を理由に人数を減らしたりしない。
- 確定後にライブ位置が変わっても、その人が現在面積に寄与する点は動かさない。未確定者のライブ位置の変化は引き続き反映する。
- `online` によって計算対象を絞らない。離席中でも選択した点を採用し、ライブ位置未送信でも確定位置があれば採用する。
- 確定座標と確定時刻が揃っていることを前提とする。確定記録の部分欠損は内部の不整合として扱い、ライブ座標で補完したり、そのプレイヤーを黙って除外したりしない。
- この選択規則はプレイ中の現在面積に適用する。confirmで使う「既存の確定点＋今回の要求座標」と、最終集計の規則はUS-13を維持する。

### 1.2 計算・API契約

- 既存の `GET /api/games/{id}` の現在面積取得経路を変更する。新規API・リクエスト・レスポンス項目・DB項目は追加しない。
- 計算は `status=ACTIVE` のときだけ行う。WAITING／COMPLETEDでは `currentArea: null` とし、完了後は保存済み `result` を使う。
- 採用できる位置が3人分未満なら `currentArea: null` を返す。3人分以上で一直線・同座標などの退化が起きた場合は、`sqm: 0` と点または線分の `hull` を返す。3人が同座標でも、人数は3人として扱う。
- `currentArea` の形は既存の `{ sqm, hull }` を維持する。`sqm` はm²の測地面積、`hull` は `[[lat,lng], ...]` の順序付き頂点列とし、多角形では閉環する。
- PostGISの `ST_ConvexHull` と `ST_Area(geography)` を使う。採用人数・凸包・面積は同じ読み取りの点群から求め、人数判定と凸包計算の間で異なる点群を使わない。
- Domainのポートに位置の選択規則と未計測・退化の契約を記し、outbound adapterが空間SQLを実行する。既存の「ライブ座標だけ」と読める命名・KDoc・コメントは新しい契約に揃える。フロントで位置を選び直して面積・凸包を再計算しない。
- 2秒ポーリング、404、プレイヤーのライブ位置・在室判定、保存済み結果の取得は維持する。GETで確定位置や結果を書き換えない。
- 確定位置のプレイヤー別返却と、確定後のマーカーの主従・薄さは[US-12](12.md)が担当する。US-20の計算は既存の保存列を使い、フロントの確定位置返却項目には依存させない。

### 1.3 上限超過の表示（D1=A）

- `currentArea.sqm > areaThreshold` では、警告文を **「上限超過」** とし、既存の超過分の数値を表示する。「このままでは確定できません」は表示しない。
- 警告色・上限・面積の整形・満杯のゲージを維持する。現在の実装に合わせ、上限接近の基準は85%以上、上限ちょうどは超過扱いにせず接近表示とする。
- 上限超過の表示は現在の配置への警告であり、今回のconfirmの成功・失敗を断定しない。超過だけを理由に確定ボタンを無効化せず、新しい確定可否の事前判定APIも追加しない。
- confirmで422が返った場合の理由別エラー表示はUS-11／US-13を維持する。メーターの警告文と、実際の確定拒否を区別する。
- 未計測では既存の「まだ計測できません（3人以上の位置が必要）」、面積0では0のゲージを表示する。上限接近の「上限に接近しています」も維持する。
- 進行中に獲得数・獲得明細・正多角形スコアを開示しない。メーターはSmartから数値を受け取るDumbのままとする。

## 2. 受け入れ条件

### API・計算

- [x] 確定済みの確定座標と、未確定のライブ座標を1人1点で採用する。
- [x] 確定後のライブ位置更新で面積・凸包が変わらず、未確定者の移動では変化する。
- [x] 確定位置とライブ位置が異なっていても、確定済みのライブ点を凸包に含めない。
- [x] 離席中の点を含み、ライブ未送信の確定者も計算対象になる。未確定・ライブ未送信は除外する。
- [x] 採用位置が2人分以下はnull、3人分以上の退化は0と点・線分のhullになる。同座標の人数を重複排除しない。
- [x] 人数・凸包・面積が同じ点群に基づき、多角形の閉環・座標順・m²の単位を維持する。
- [x] 確定記録の部分欠損をライブ位置や対象除外で隠さない。
- [x] WAITING／COMPLETEDのcurrentAreaはnull。既存API形式・エラー・confirm・結果保存の契約を維持する。

### フロント

- [x] ポーリングで返った面積と凸包をそのまま表示し、クライアントで再計算しない。
- [x] 上限超過時は「上限超過」と超過分を表示し、今回の確定可否を断定しない。
- [x] 警告色・上限接近・上限ちょうど・未計測・面積0・数値整形の既存表示を維持する。
- [x] メーターの超過だけでは確定ボタンを無効化せず、confirmの422によるエラー表示は維持する。
- [x] スコア非開示、Smart／Dumbの分離、完了時の結果画面への遷移を維持する。

## 3. テスト観点

テスト名は `test_Action_Condition_Result` とし、実ソースを対象にする。フロントのテストは `frontend/tests/` にsrcをミラーして配置する。

- **Level 1: Domain** — US-13の確定時の上限・下限・再確定不可の規則が変わらないことを回帰確認する。現在面積の警告から新しい業務上の拒否を作らない。
- **Level 2: UseCase** — ポートをモックし、ACTIVE時だけ現在面積を取得してそのまま返すこと、他の状態のnull、ライブ時刻による在室判定と結果返却の維持を確認する。
- **Level 3: 永続化** — 実PostGISで、固定点が三角形を作り、確定済みのライブ点が遠方にあるデータを使う。固定点の優先・1人1点・ライブ更新前後の不変・未確定者の移動による変化を検証する。採用人数0〜2／3、固定とライブの混在、liveなし、離席、全点同座標、一直線、閉環、部分欠損も扱う。
- **Level 3: Web** — `@WebMvcTest` でcurrentAreaの既存形式・null・0と、既存エラー・状態別の返却を確認する。
- **フロント** — 接近基準の直前／85%／上限ちょうど／超過、未計測／0、超過分と警告文を検証する。現在面積が超過していても最初のconfirmが受理されるケースを結線で再現し、表示が確定不能と断定しないことを確認する。
- **実ブラウザ** — US-12と合わせ、確定者が移動しても確定点・現在面積・凸包が留まり、未確定者の移動だけが面積に反映されることを確認する。GPS送信元はプレイヤーごとに1つとし、重複タブや位置更新スクリプトを競合させない。

## 4. スコープ

### 含む

- プレイ中の現在面積の計算入力変更と、それに伴う取得契約・命名・説明の整合。
- 「上限超過」と超過分の警告表示、および関連テストの修正。
- US-08／US-09／US-10／DESIGNの上流契約と、US-12との担当境界の更新。

### 含まない（他ストーリー／将来）

- 確定位置のAPI返却と、名前付き確定マーカー・確定後のライブ位置の薄い表示（US-12）。
- 参加直後の不在表示（US-21）、確定取消・上書き（US-17）。
- confirmの判定対象・面積条件・集計・保存済み結果の変更（US-11／US-13／US-15）。
- 在室者だけへの計算対象の絞り込み、新しい確定可否API、フロントでの空間計算。

### 判断ログ（3 Amigos）

| # | 論点 | 判断 | 理由 |
| --- | --- | --- | --- |
| 位置の採用 | 現在面積の入力 | 確定済みは固定点、未確定はライブ点を1人1点使う。 | 確定後の移動でゲーム上の配置を変えないという利用者の合意。 |
| 対象の確認 | 計算する場面 | プレイ中のGETが返すcurrentAreaの計算を変更する。 | 計算場所は既存どおりサーバー。確定時・結果取得とは区別する。 |
| D1 | 超過の文言 | A。「上限超過」と超過分だけを表示する。 | 利用者がAを選択。現在面積から今回の確定可否を断定しない。 |
| 境界の継承 | 未計測・退化・離席 | 採用位置3人分未満はnull、3人分以上の退化は0。onlineで対象を除外しない。 | US-08の意味を維持し、採用する座標だけを拡張する。 |
| 実装単位 | US-12との分離 | 計算と警告をUS-20、確定状態・位置の表示をUS-12とする。 | 利用者の指示により、既存US-12へ他の課題を混ぜない。 |

### 前提

- US-11で確定座標・時刻は保存済み。US-20は新しい保存領域を必要としない。
- 現在面積は全員の配置の目安であり、個別のconfirmと入力点が異なる。面積条件の最終的な判断はconfirm時にサーバーが行う。
- US-12の主表示・補助表示と合わせて画面検証する。US-20自体はプレイヤー別の確定位置返却には依存しない。
