# 01-spec.md — US-10: 面積メーター（凸包面積 vs 上限閾値）

> プレイヤーとして、現在の凸包面積（面積メーター）を見たい。
> 閾値に対してどこまで広げたか判断するため。
> 本仕様は1実装単位（US-10）分。Phase 2（実装）へ引き継ぐ。

---

## 1. 合意された仕様

### 1.0 ゲームルールの前提（重要・認識合わせ）

- `areaThreshold` は **面積の「上限」**（CLAUDE.md）。
- 確定済み位置と今回の要求座標から作る凸包が上限を超える場合、そのconfirmを拒否する（US-13）。現在面積は未確定者のライブ位置も含むため、メーターの超過と今回の確定可否は同じ判定ではない。
- **面積が下限閾値 `areaMinThreshold` を下回る最終確定もできない（確定不能）**（面積0付近を実用的に扱う。US-13。散らばって確定し直す）。上限・下限どちらの無効面積でも確定は弾かれるため、**正常系では結果が無効面積になることはない**。
- `objectCount`（得点）は面積成立時に凸包内へ内包される対象数。面積は上限内で広く囲むことを目指すが、現在面積の表示だけで確定可否を断定しない。
- したがって面積メーターは「目標に届かせる」ゲージではなく、**「上限を超えないよう見張りつつ、上限ギリギリを狙う」ゲージ**。

### 1.1 データ源（API 変更なし）

- データ源は US-08 の `currentArea.sqm` と `areaThreshold`（GET レスポンスに含む）。
- 現在面積の採用点は[US-20](20.md)を正とする。確定済みは確定座標、未確定はライブ座標をサーバーが1人1点選び、面積と凸包を返す。
- `objectCount` は伏せる（確定まで）／正多角形スコアも伏せる（将来 `regularityHint` のみ）。表示は面積のみ（X3）。

### 1.2 メーターの表示（G1: 案A）

- **進捗ゲージ（0〜`areaThreshold` を満杯とするバー）＋現在面積の数値**を表示。上限（`areaThreshold`）を「満杯ライン」として明示する。
- 現在面積が上限に**近づくと警告表示**（色変化など）。上限は「超えてはいけない線」であり「到達目標」ではない旨が伝わる見せ方にする。
- 上限接近は現行の85%以上を維持し、上限ちょうどは超過扱いにしない（US-20）。
- 面積は大きいほど有利なので、上限手前まで攻める行動を妨げない表現にする（警告＝「近い、超えるな」であって「下げろ」ではない）。

### 1.3 上限超過時の表示（G4: US-20で改訂）

- 現在面積が `areaThreshold` を超えたら「上限超過」を表示する。ゲージは満杯・警告色とし、今回の確定可否を断定する文言は添えない（US-20 D1=A）。
- 超過分の数値も見せ、「どれだけ超えているか（縮める目安）」を分かるようにする。
- 「確定できます／確定できません」や「失格／無効／達成」といった表示は出さず、現在の配置への警告として見せる。超過だけでは確定ボタンを無効化しない。実際の確定拒否と422の表示はUS-11／US-13を維持する。
- 進行中の over/under 表示は、クライアントが持つ2つの数値（`currentArea.sqm` と `areaThreshold`）の**スカラー比較**で行う。凸包・面積・内包の計算はしない（サーバー計算値の単純比較なので CLAUDE.md の非計算方針に反しない）。権威ある判定は確定時サーバー側。

### 1.4 未計測（`currentArea=null`）の表示（G3: 案A）

- `currentArea=null`（採用位置が3人分未満）のときは、**0%ではなく「まだ計測できません（3人以上の位置が必要）」の未計測表示**にする。確定位置も採用人数に含む。ゲージは空／グレー。
- E2=B（3点未満は `null`）の意図（バグっぽい 0 を出さない）とそろえる。
- 退化（`sqm=0`・一直線）は「面積ゼロ」の正当な値としてゲージ 0 側で表示（未計測とは区別）。

### 1.5 単位・表示形式（G2: 案A）

- 面積はkm²に統一して表示し、桁区切りを付ける（例: small = 500,000m² → 0.50 km²、medium = 2,000,000m² → 2.00 km²）。待機画面・ウォークスルー・結果も同じ規則を使う。
- 小数は最低2桁、最大6桁とし、1m²単位の小さい値もゼロに丸めない。API・比較・計算上の値はm²のまま維持する（2026-11-09、利用者の表示単位変更指示）。

### 1.6 コンポーネント構成 / 将来の拡張余地（G5: 案A）

- Smart（コンテナ）が US-08 の状態（`currentArea` / `areaThreshold`）を受け取り、Dumb メーターに props（`sqm` / `threshold`）で渡すだけ。Dumb は API を知らない。
- **面積メーター単体**で作る。将来の正多角形ヒント（`regularityHint`）ゲージは**兄弟要素として横に足せるレイアウト**にしておく（汎用枠の先取りはしない）。

## 2. 受け入れ条件

- [ ] 現在の凸包面積が数値で表示される（人間可読な単位・桁区切り）。
- [ ] `areaThreshold` を満杯ラインとする進捗ゲージが表示される。
- [ ] 現在面積が上限に近づくと警告表示になる。
- [ ] 現在面積が上限を超えると「上限超過」と超過分を表示し、今回の確定可否を断定しない。超過だけでは確定ボタンを無効化しない。
- [ ] 超過時に超過分（どれだけ超えているか）が分かる。
- [ ] 「確定できます／達成」等、閾値到達を成功として促す表示は出ない。
- [ ] `currentArea=null` のとき 0% ではなく「未計測」表示になる。
- [ ] 退化（`sqm=0`）のときは未計測ではなくゲージ 0 側で表示される。
- [ ] `objectCount`・正多角形スコアは一切表示されない。
- [ ] メーターは 2秒ごとに現在面積を反映して更新される。
- [ ] メーターは Dumb で、API を知らない（Smart から props で受け取る）。

---

## 3. テスト観点

- **ゲージ**: `sqm < threshold` で通常、上限近傍で警告、`sqm > threshold` でオーバー表示。境界（`sqm == threshold`）の扱い。
- **数値整形**: 小さい/大きい面積が可読な単位・桁区切りで出る。
- **未計測**: `currentArea=null` で「未計測」表示（0% にしない）。`sqm=0`（退化）はゲージ 0 側で未計測と区別。
- **情報マスキング**: objectCount・正多角形スコアが描画されないこと（回帰防止）。「達成/確定」文言が出ないこと。
- **更新**: ポーリング（2秒）で `sqm` 変化がメーターに反映される（fake timer）。
- **Dumb 分離**: メーターコンポーネントが API を import しない。props（sqm/threshold）のみで描画。

## 4. スコープ

### 含む

- 面積メーター（現在面積の数値＋上限ゲージ）。
- 上限接近・現在面積の上限超過への警告と、超過分の表示。
- `currentArea=null` の未計測表示・退化（sqm=0）との区別。
- 面積の人間可読な整形（単位・桁区切り）。
- 将来の正多角形ゲージを横に足せるレイアウト（面積メーター単体で実装）。
- Smart/Dumb 分離。

### 含まない（他ストーリー / 将来）

- 位置確定（confirm）・確定ボタン・二重確定防止（US-11）。
- 権威ある `areaValid` 判定・自動集計・`result`（US-13）。進行中の over/under はクライアントの表示上の目安に留める。
- `objectCount`（獲得数）の表示（確定まで伏せる）。
- 正多角形 `regularityHint` ゲージの実装（追加要件レイヤー。MVP 完了後にフィールド追加＋兄弟ゲージ追加で対応）。
- 凸包頂点・面積のクライアント計算（サーバー計算。禁止）。
- 面積のちらつき対策（補間/平滑化）は必要なら実装時判断（スコープ外寄り）。

### 前提

- `areaThreshold` は作成時に確定（GET レスポンスに含む）。メーターはこれを上限ラインに使う。
- 現在面積は確定済みの確定位置と未確定のライブ位置からサーバーが計算し、2秒ポーリングで表示する（US-20）。確定後のライブ移動では面積を変えない。
- 進行中の over/under は表示上の目安。最終判定は確定時にサーバーが `areaValid` を確定（US-13）。
