# 01-spec.md — US-09: 友達ドット＋凸包の形を地図に表示

> プレイヤーとして、地図上に他プレイヤーのライブ位置（友達ドット）と、
> 全員で作っている面積の形（凸包）を見たい。誰がどこにいて、どんな形になっているか把握するため。
> 本仕様は1実装単位（US-09）分。Phase 2（実装）へ引き継ぐ。

---

## 1. 合意された仕様

### 1.1 データ源（API 変更なし）

- データは US-08 の `GET /api/games/{id}` から取得: `players[].live` / `players[].online` / `currentArea.hull` / `currentArea.sqm`。
- 本 US は**フロントの描画のみ**。バックエンド変更なし（凸包頂点の返却は US-08 で対応済み）。
- 凸包の頂点はサーバーが計算して返す。**クライアントは凸包を計算せず、受け取った頂点をそのまま描く**（CLAUDE.md）。

### 1.2 マーカーの描画

react-leaflet で以下を描く。Leaflet は描画専用。

- **自分**: US-02 の `watchPosition` の**リアルタイム位置**を正として描画（F1: 案A）。GET 内の自分要素は描画に使わない。
- **他プレイヤー（友達ドット）**: US-08 の `players[].live` を描画（2秒ごと更新）。
- 自分ドットと友達ドットは色/形で視覚的に区別する（デザイン詳細は実装時）。
- 各ドットに**常時、控えめな displayName ラベル**を添える（F3: 案A）。
- **離席（`online=false`）プレイヤー**は最後の live 位置に**グレーアウト（半透明）で残す**（F2: 案A）。凸包（面積）に離席者の最終点が含まれる（US-08 E1=A）ことと地図の見た目を一致させる。live 未送信（live=null）のプレイヤーはドットを描かない。

### 1.3 凸包の形（面積の形）の描画

- `currentArea.hull`（`[[lat,lng],...]` 閉環）を **Leaflet の Polygon として描く**（F5: 案B）。頂点はサーバー提供。
- `currentArea = null`（live 点 3点未満）のときはポリゴンを描かない（形が未成立）。
- 退化（一直線・`sqm=0`）のときは線分として描かれる（頂点列をそのまま描画）。
- ポリゴンは塗り＋輪郭の控えめな表示。友達ドットの上に重ならず形が読める描画にする（デザイン詳細は実装時）。
- **表示するのは「形」と面積数値（US-10）まで**。正多角形スコアは伏せる（将来 `regularityHint` のみ）／`objectCount` も伏せる。形を見せることで、将来の正多角形追加要件で「形を整える」調整を可能にする布石。

### 1.4 ビューポート（全員＋形が入るように）

- 自分・友達ドット・凸包ポリゴンの**全頂点が画面に収まるよう `fitBounds`** する（F4: 案B）。凸包の形を見ながら位置を調整できるようにするため。
- **カメラの暴れ対策**（F4=B の副作用への対処。実装方針）:
  - 毎ポーリング（2秒）で無条件に再フィットしない。**bounds が有意に変化したときだけ**再フィット（閾値以下の微小変化では動かさない）。
  - ユーザーが手動でパン/ズーム操作中は自動フィットを**一時停止**し、操作が落ち着いてから追従を再開する。
  - 「全体表示」ボタン（手動リフィット）を用意し、ユーザーが任意で全体に戻せるようにする。
  - US-02 の自分追従（自分中心）は、この全体フィットに置き換わる（自分中心固定は維持しない）。

### 1.5 コンポーネント構成

- Smart（コンテナ）が US-08 のポーリング状態（live / online / hull など）を受け取り、Dumb コンポーネント（地図・マーカー・ポリゴン）に props で渡すだけ。Dumb は API を知らない。

---

## 2. 受け入れ条件

- [ ] 他プレイヤーの live 位置が友達ドットとして地図に描画される。
- [ ] 自分の位置は `watchPosition` のリアルタイム値で描画され、友達ドットと視覚的に区別される。
- [ ] 各ドットに displayName ラベルが常時表示される。
- [ ] `online=false` のプレイヤーが最後の位置にグレーアウト表示される。
- [ ] `live=null`（未送信）のプレイヤーはドットが描かれない。
- [ ] `currentArea.hull` があるとき、凸包ポリゴンが地図に描画される。
- [ ] `currentArea=null`（3点未満）のときポリゴンが描かれない。
- [ ] 退化（`sqm=0`）のとき線分として描画され、破綻しない。
- [ ] 自分・友達・凸包の全頂点が画面に収まる（`fitBounds`）。
- [ ] ユーザーが手動操作中は自動フィットが一時停止し、カメラが暴れない。
- [ ] 「全体表示」ボタンで全体にリフィットできる。
- [ ] `objectCount` や正多角形スコアは一切表示されない。
- [ ] 描画に必要な API 呼び出しは Smart（コンテナ）からのみ行われる。

---

## 3. テスト観点

- **マーカー描画**: `players[].live` から友達ドットが N-1 個描かれる。自分は watchPosition ソースで別描画。
- **online 反映**: `online=false` でグレーアウト、`live=null` で非描画。
- **ラベル**: displayName が各ドットに出る。
- **ポリゴン**: `hull` からポリゴンが描かれる／`currentArea=null` で非描画／退化で線分描画。
- **fitBounds**: 全頂点が bounds に含まれる。bounds 微小変化では再フィットしない（fake timer）。手動操作中は自動フィット停止、「全体表示」で復帰。
- **情報マスキング**: レスポンスに objectCount が無いこと・正多角形スコアを描画しないこと（回帰防止）。
- **Dumb 分離**: 地図/マーカー/ポリゴンコンポーネントが API を import しない。

---

## 4. スコープ

### 含む

- 友達ドット（他プレイヤー live 位置）の描画・displayName ラベル・自分/友達の視覚区別。
- 離席（online=false）のグレーアウト表示、live=null の非描画。
- 凸包ポリゴン（`currentArea.hull`）の描画（サーバー提供頂点をそのまま描く）。
- 全頂点を収める `fitBounds`＋カメラ暴れ対策（有意変化のみ再フィット・手動操作中は停止・全体表示ボタン）。
- Smart/Dumb 分離の維持。

### 含まない（他ストーリー / 将来）

- 面積メーター（数値表示・閾値ゲージ）（US-10）。
- 凸包頂点の返却（US-08 で対応済み。ここでは描くだけ）。
- クライアント側での凸包・面積計算（サーバーが計算。禁止）。
- マーカーの補間（ぬるぬる移動）。2秒ごとに飛ぶ表示で可。
- 位置確定（confirm）・確定ポリゴン（`result.polygon`）の描画（US-11 / 結果表示）。
- `objectCount` の表示（確定まで伏せる）。
- 正多角形 `regularityHint` の表示（追加要件レイヤー。MVP 完了後）。ただし形が見えている状態は将来の布石として用意する。

### 判断ログ（3 Amigos）

| # | 論点 | 判断 | 理由 |
|---|---|---|---|
| F1 | 自分の描画ソース | 案A: 自分=watchPosition / 他=GET live | 自分は手元にリアルタイム値がある。自分だけ即応、他人は2秒で十分 |
| F2 | 離席プレイヤーのドット | 案A: 最後の位置にグレーアウト | 凸包に離席者の最終点を含む（E1=A）ので地図と面積の形を一致させる |
| F3 | displayName ラベル | 案A: 常時表示 | 「誰がどこ」を一目で。N=3 規模なら混雑許容 |
| F4 | ビューポート | 案B: 全員＋形が入る fitBounds | 凸包の形を見ながら調整したい。カメラ暴れは実装で緩和 |
| F5 | 凸包の形の描画 | 案B: サーバー提供頂点でポリゴン描画 | 進行中も形を見せる。将来の正多角形要件で形調整を可能に。クライアント非計算は維持。US-08 の契約に頂点追加を反映済み |

### 前提

- 自分（watchPosition）と GET 内の自分 live が2秒ズレるが、自分は watchPosition を正とし GET の自分要素は描画に使わない。
- 友達ドットは最大 N-1（MVP は2）で描画負荷は無視可能。
- 形を見せる＝情報開示が増えるが、開示するのは「形＋面積数値」まで。スコア（objectCount）・正多角形スコアは伏せる方針を維持。
