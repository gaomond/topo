# 01-spec.md — US-12: 全員の確定状態と確定位置の表示

> プレイヤーとして、誰がどこで確定したかを見たい。全員の進捗と、ゲームで使う確定位置を把握するため。
> 本仕様は1実装単位（US-12）分。実装・検証・独立レビュー承認済み（2026-11-10）。

現在は、確定した本人の画面だけが確定時の座標を保持している。他の参加者は確定状態を取得できても、確定座標を取得できず、地図に確定位置を表示できない。保存済みの確定位置を状態取得で返し、全員の画面で共有する。

確定後は確定位置を主表示とする。ライブ位置も移動状況を知るために残すが、本人・他プレイヤーとも薄く表示する。

```text
位置を確定 → 本人は成功応答で確定位置を即時表示
  → 他の参加者は既存の2秒ポーリングで確定位置を取得・表示
  → 確定後に移動してもチェックマークは固定し、ライブ位置だけが薄い表示で移動
  → 再読み込み時も保存済みの確定位置を表示
```

## 1. 合意された仕様

### 1.1 API: 全員の確定位置を返す

既存の `GET /api/games/{id}` の各プレイヤーに、必須の `confirmedLocation` キーを追加する。新規エンドポイント・リクエスト項目は追加しない。

```json
{
  "playerId": "...",
  "displayName": "hello",
  "confirmed": true,
  "confirmedLocation": {
    "lat": 35.59,
    "lng": 139.60,
    "at": "2026-11-09T12:00:00Z"
  },
  "live": {
    "lat": 35.591,
    "lng": 139.601,
    "at": "2026-11-09T12:01:00Z"
  },
  "online": true
}
```

| 項目 | 契約 |
| --- | --- |
| `confirmed` | 既存の真偽値を維持する。未確定はfalse、確定済みはtrue |
| `confirmedLocation` | 未確定はnull。確定済みは保存済みの座標と確定時刻を返す |
| `confirmedLocation.lat` / `lng` | WGS84の緯度・経度。`fixed_geom` から取得する |
| `confirmedLocation.at` | `confirmed_at`。ISO-8601のUTC表記（末尾Z）で返す |
| `live` / `online` | 最新ライブ位置と、その記録時刻による在室判定。確定位置で置き換えない |

- 自分と他プレイヤーで返却項目を分けない。WAITING・ACTIVE・COMPLETEDを通じて同じプレイヤー形式とし、状態による画面分岐は既存仕様を維持する。
- `confirmed` と `confirmedLocation` は同じ保存済みの確定記録から作り、trueなのにnullとなる応答を返さない。確定時刻だけ、または確定座標だけが存在する不整合を、未確定やライブ座標への置換で隠さない。
- ライブ位置が未送信でも確定位置は返す。離席・ライブ位置更新によって確定位置と確定時刻を変更しない。
- 既存の参加者順、404、ポーリング周期、完了結果の返却を維持する。新しい認証や参加者チェックは追加しない。
- confirmのリクエスト・成功応答・400／404／409／422は変更しない。確定操作と面積検証はUS-11／US-13を正とする。

### 1.2 Domain・取得経路

- 保存済みの確定位置には、既存のDomain値 `ConfirmedLocation`（`Coordinate` と確定時刻）を使う。
- `PlayerReading` と `PlayerSnapshot` にnullableな確定位置を持たせ、既存の `PlayerRepositoryPort.findByGameId` からUseCaseを通じてWebへ渡す。座標・時刻・確定状態の整合は読み取り時にも守る。
- 一覧取得時に全員の確定位置を取得する。人数分の個別プレイヤー取得や、専用の確定位置取得APIを追加しない。
- Web表現は `ConfirmedLocationPayload` とし、DomainにJSON・JPA・PostGISの型を持ち込まない。既存の `fixed_geom` と `confirmed_at` を使うため、DBスキーマ変更は不要。

### 1.3 地図上の主表示と補助表示（D1=A）

| プレイヤーの状態 | 確定位置 | ライブ位置 |
| --- | --- | --- |
| 未確定 | 表示しない | 既存の自分ピン／友達ドットを表示する |
| 確定済み | 名前付きチェックマークを通常の濃さで表示する | 本人・他プレイヤーとも、マーカーと付随する名前を薄く表示する |
| 確定済み・ライブ位置なし | 確定位置のチェックマークを表示する | 表示しない |
| 確定済み・離席 | 確定位置のチェックマークを通常の濃さで残す | 最後のライブ位置を薄く表示する |

- 確定位置がゲーム上の主となる点であり、ライブ位置は確定後の現在地を示す補助情報とする。両者を同じ強度で表示しない。
- 確定マーカーにはdisplayNameを添え、誰の確定位置か分かるようにする。自分と他プレイヤーのライブ位置の視覚的な区別は維持する。
- 薄さの具体値は実装時に決めるが、未確定の在室者のライブ位置より明確に薄く、確定マーカーより弱い表示にする。離席も重なる場合に透明度を重ね掛けして見えなくしない。
- ライブ位置と確定位置が重なる場合はチェックマークとその名前を読める描画順にする。座標をずらして重なりを解消しない。別プレイヤー同士の同座標での重なりは今回許容する。
- 自分のライブ位置は引き続き `watchPosition`、他プレイヤーはGETの `live` を使う。確定後もACTIVE中の測位・ライブ位置送信は継続する。
- 確定位置も既存の全体表示・fitBoundsの対象に含める。カメラの微小変化・手動操作への配慮はUS-09を維持する。
- 名前はテキストとして安全に表示し、LeafletのHTMLへ直接埋め込む場合は既存と同様にエスケープする。

### 1.4 即時反映・再訪・応答の前後関係

- 本人のconfirm成功時は、実際に送信して受理された座標を即時に確定位置として表示し、ライブ位置を薄くする。次のGETを待たない。
- 再訪・再読み込み・他の画面からの確定は、GETの保存済み確定位置を使う。現在地や最後に送信したライブ位置から確定位置を推測しない。
- confirm成功後に古いGETが未確定を返しても、確認済みの本人の確定状態・位置を巻き戻さない。保持する値はgameId・playerIdに対応付け、別の参加者やゲームへ持ち越さない。
- 409後の既存の状態再取得で本人が確定済みと分かった場合は、そのGETの確定位置を表示する。409で拒否された今回の送信座標を確定位置として扱わない。
- 422などで確定が拒否された場合は、チェックマークを追加せず、確定後の薄い表示にも切り替えない。
- 他プレイヤーのチェックマークは既存ポーリングで反映する。確定位置表示のためだけの追加ポーリングは設けない。
- 最終確定からの結果表示と、COMPLETEDへの再訪はUS-14／US-15を維持する。結果画面に全プレイヤーの確定点を追加する変更は含めない。

### 1.5 面積表示との境界

確定後に面積へ使う点は確定位置とする。この方針は合意済みであり、ライブ位置は面積の入力として確定位置と同格に扱わない。

`currentArea`の計算変更と面積超過の警告文は[US-20](20.md)で扱い、位置の採用規則は同仕様を正とする。US-12の実装範囲は、確定位置の返却とマーカーの表示・主従の区別とする。フロントに面積計算を追加しない。

## 2. 受け入れ条件

### API

- [x] 全プレイヤーに `confirmedLocation` キーがあり、未確定はnull、確定済みは保存済みのlat・lng・atを返す。
- [x] `confirmed` と確定位置の有無が一致し、確定記録の部分欠損をライブ位置や未確定扱いで補完しない。
- [x] 確定後にライブ位置が更新されても確定位置・時刻は変わらず、両方を区別して返す。
- [x] ライブ位置未送信・離席でも、保存済みの確定位置を返す。
- [x] 参加者順、既存の状態別レスポンス・エラー・confirm契約を維持する。

### フロント

- [x] 他プレイヤーの確定がポーリングで反映され、名前付きチェックマークを保存済み位置に表示する。
- [x] 本人は成功応答で即時表示し、再読み込み時もGETから正しい確定位置を表示する。
- [x] 確定後のライブ位置は本人・他プレイヤーとも薄く、確定位置は通常の濃さで表示する。移動しても確定マーカーは動かない。
- [x] ライブ位置なし・離席でも確定マーカーは消えず、離席によって確定マーカーを薄くしない。
- [x] 同じプレイヤーのライブ位置と確定位置が重なっても、チェックマークと名前を読める。
- [x] 古いGETによる本人の確定表示の巻戻り、別gameId・playerIdへの持ち越しがない。
- [x] 409後は取得した保存済み位置を使い、422では確定表示へ変えない。
- [x] 確定位置が全体表示に含まれ、既存の結果遷移・GPSの扱い・ライブ送信・Smart／Dumbの分離を維持する。

## 3. テスト観点

テスト名は `test_Action_Condition_Result` とする。フロントのテストは `frontend/tests/` にsrcをミラーし、実ソースをimportする。

- **Level 1: Domain** — 既存の `ConfirmedLocation` を再利用し、再確定不可・保存済み位置不変の契約を維持する。表示のために確定ルールを追加しない。
- **Level 2: UseCase** — プレイヤー取得ポートをモックし、未確定・確定済み・liveなし・離席の確定位置が `PlayerSnapshot` に渡り、在室判定が確定時刻へ切り替わらないことを確認する。
- **Level 3: 永続化** — 実PostGISで確定位置とライブ位置が異なる複数人を取得する。ライブ更新後も固定点・時刻が変わらないこと、一覧順と確定状態の整合、確定記録の部分欠損を補完しないことを検証する。
- **Level 3: Web** — `@WebMvcTest` でnullとオブジェクト、lat／lngの対応、UTC時刻、全プレイヤーで共通の形式、既存エラーを検証する。
- **フロント** — ポーリング前後の他人の表示、本人の即時反映・再読み込み・409再取得・422・遅延GET・セッション切替を検証する。確定後にliveを変え、チェックマークだけが保存済み位置に留まり、ライブ表示だけが薄く移動することを確認する。
- **実ブラウザ** — 2人以上の画面で確定を共有し、確定後の移動・再読み込み・名前の視認性・同位置での描画順を確認する。薄さの確認はモック地図のprops検証だけで完了としない。通常のAPIと各プレイヤー1つのGPS送信元を使い、同じplayerIdの重複タブや別の位置更新スクリプトを混在させない。

## 4. スコープ

### 含む

- 既存GETへの確定位置追加と、読み取り射影・Web表現の拡張。
- 全員の名前付き確定マーカーと、確定後のライブ位置の補助表示。
- 本人の即時反映・再訪・既確定時の復元、遅延応答とセッション切替への対処。
- 関連するUS-08／US-09／US-11の取得・表示契約の整合。

### 含まない（他ストーリー／別修正）

- 現在面積への確定座標の反映と、上限超過の警告文の変更（US-20）。
- 参加直後の一時的な不在表示（US-05の不具合修正）。
- 確定操作・面積判定・最終集計の変更（US-11／US-13／US-15）。
- 確定取消・再確定（US-17）、進捗一覧など地図以外の新しい画面部品。
- 結果画面への全員の確定点追加、GPS許可エラー時の画面分岐変更。

### 判断ログ（3 Amigos）

| # | 論点 | 判断 | 理由 |
| --- | --- | --- | --- |
| 対象 | 実装単位 | 他プレイヤーの確定状態・位置表示をUS-12として扱う。面積・警告・参加直後の修正を混ぜない。 | 既存US-12そのものの目的であり、他の課題とは分けるという利用者の指示。 |
| D1 | 確定後のライブ位置 | A。確定位置とライブ位置を両方表示する。 | 現在地の共有を維持しながら、確定した場所を確認するため。 |
| D1補足 | 表示の主従 | 確定位置を主表示とし、本人・他人とも確定後のライブ位置を薄くする。 | 両方の点を同じ強度で扱わないという利用者の指示。 |
| 面積との関係 | 確定後の採用点 | 面積では確定位置を使う。現在面積の計算変更は別修正として維持する。 | 確定位置がゲーム上の点であり、確定後の移動で面積を変えないため。 |
| API | 確定位置の共有 | 既存GETへnullableなconfirmedLocationを追加し、既存のConfirmedLocationと保存列を使う。 | 新規API・保存領域を増やさず、本人の復帰と他人の表示を同じ値で扱える。 |

### 前提

- US-11／US-13により、確定記録は座標と時刻が同一Txで保存され、再確定で変更されない。
- 在室判定はUS-08のライブ記録時刻を使う。離席と確定状態は別の概念とする。
- US-14／US-15の完了時の結果表示・測位とライブ送信の終了を維持する。

## 5. 実装・検証記録（2026-11-10）

保存済みの確定位置を既存GETから全員へ返し、名前付きチェックを主表示、確定後のライブ位置を不透明度0.4の補助表示とした。確定位置は不透明度1で、同位置のライブよりz-indexを10000高くする。読み取り型の確定状態は確定位置の有無から導出する。

| 受け入れ条件 | 確認方法 |
| --- | --- |
| 必須nullableキー・UTC時刻・全状態で共通の形式 | GameStateControllerTest / OpenApiContractTest |
| 固定値とliveの分離・liveなし・離席・参加順・一括SELECT・部分欠損拒否 | LiveLocationPersistenceTest（実PostGIS）/ GetGameStateUseCaseTest |
| 本人の即時反映・遅延GET・再訪・409・422・セッション切替 | useLocationConfirmation.test.ts / GeoTrackingContainer.test.tsx |
| 名前の安全表示・濃度・同位置の前後関係・全体表示 | MapView.test.tsx / 実ブラウザ3画面 |
| 保存点共有・移動後固定・離席・GPSなし再読み込み・結果遷移 | 通常APIと実Leafletによるブラウザ検証 |
