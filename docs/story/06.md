# 01-spec.md — US-06: 作成者が開始ボタンで ACTIVE に遷移

> 作成者として、N人揃ったら開始ボタンを押して ACTIVE に遷移させたい。
> 開始タイミングを自分でコントロールするため。
> 本仕様は1実装単位（US-06）分。Phase 2（実装）へ引き継ぐ。

---

## 1. 合意された仕様

### 1.1 API: `POST /api/games/{id}/start`

ドキュメントの6本APIに追加する1本。

#### リクエスト

```json
{
  "playerId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
}
```

| フィールド | 型 | 必須 | 備考 |
|---|---|---|---|
| `playerId` | UUID | ○ | リクエスト元のplayerId。creator判定に使用 |

#### サーバー処理

1. `game.id` の存在確認。なければ404。
2. `game.status = WAITING` であること。ACTIVE/COMPLETEDなら409。
3. `playerId` が `game.creator_player_id` と一致すること（作成者のみ）。不一致は403。
4. 参加者数 = `game.player_count`（定員ちょうど）であること。未達なら409。
5. 同一Tx内で `game.status` を `ACTIVE` に更新。他カラムは変更しない。

#### レスポンス（200 OK）

```json
{
  "gameId": "...",
  "status": "ACTIVE"
}
```

#### エラーレスポンス

| 条件 | コード |
|---|---|
| gameId が存在しない | 404 |
| 作成者でない | 403 |
| 開始できない（status が WAITING 以外 / 定員未達） | 409 |

### 1.2 フロントエンド: 開始ボタン

#### 表示

- 待機画面（US-04/05で構築済み）に開始ボタンを配置。
- **全員に表示**する。非作成者は非活性（押せない）。
- 作成者であっても、定員未達の間は非活性。定員到達で活性化。
- creator判定: URLの `playerId` と `GET /api/games/{id}` レスポンスの `creatorPlayerId` を比較。

#### 押下時

1. `POST /api/games/{id}/start` を `playerId` 付きで呼ぶ。
2. 200が返ったら地図画面に遷移。

### 1.3 ACTIVE検知後の画面遷移

- 作成者: 開始ボタン押下→200→地図画面に遷移。
- 非作成者: ポーリング（US-05で構築済みの共通基盤）で `status = ACTIVE` を検知→地図画面に遷移。
- 地図画面はUS-02の雛形（Leaflet＋GPS）がベース。友達ドット・面積メーター等の中身はUS-07〜10で実装する。US-06では「ACTIVEになったら地図画面に切り替わる」遷移のみ。

### 1.4 `GET /api/games/{id}` レスポンスへの追加

US-06の実装に伴い、既存のGETレスポンスに `creatorPlayerId` フィールドを追加する。開始ボタンの表示制御（creator判定）に必要。

---

## 2. 受け入れ条件

### API

- [ ] `POST /api/games/{id}/start` に作成者のplayerIdで呼ぶと200が返り、`game.status` が `ACTIVE` に更新される。
- [ ] 作成者でないplayerIdで呼ぶと403が返る。
- [ ] 定員未達の状態で呼ぶと409が返る。
- [ ] status が ACTIVE / COMPLETED の状態で呼ぶと409が返る。
- [ ] 存在しない gameId で404が返る。
- [ ] `GET /api/games/{id}` のレスポンスに `creatorPlayerId` が含まれる。

### フロント

- [ ] 待機画面に開始ボタンが全員に表示される。
- [ ] 非作成者は開始ボタンが非活性で押せない。
- [ ] 作成者でも定員未達の間は開始ボタンが非活性。
- [ ] 定員到達後、作成者の開始ボタンが活性化する。
- [ ] 開始ボタン押下後、地図画面に遷移する。
- [ ] 非作成者はポーリングでACTIVEを検知し、地図画面に遷移する。

## 3. テスト観点

### API

- **正常系**: 作成者・定員到達・WAITING→ 200、DBのstatusがACTIVE。
- **権限**: 非creatorのplayerIdで403。
- **定員未達**: N人中(N-1)人の状態で409。
- **ステータス**: ACTIVE/COMPLETEDのゲームに対して409。
- **冪等性**: 同じリクエストを2回送った場合、1回目は200、2回目は409（すでにACTIVE）。

### フロント

- **ボタン制御**: creator＋定員未達→非活性。creator＋定員到達→活性。非creator＋定員到達→非活性。
- **遷移（作成者）**: ボタン押下→地図画面に切り替わる。
- **遷移（非作成者）**: ポーリングでACTIVEを検知→地図画面に切り替わる。検知の遅延はポーリング間隔に依存（許容）。
- **地図画面の初期状態**: US-02の雛形（地図＋自分ピン）が表示される。友達ドット・面積メーターはまだ無い（US-07〜10）。

---

## 4. スコープ

### 含む

- `POST /api/games/{id}/start` API（creator判定・定員チェック・ステータス更新）。
- `GET /api/games/{id}` への `creatorPlayerId` フィールド追加。
- 待機画面への開始ボタン配置（活性/非活性制御）。
- ACTIVE検知→地図画面への遷移（作成者: 即時、非作成者: ポーリング検知）。

### 含まない（他ストーリー / 将来）

- 地図画面の中身（友達ドット・面積メーター・ライブ位置送信）はUS-07〜10。
- ポーリング基盤自体の構築はUS-05で実施済み。US-06はそれを利用するだけ。
- 途中参加（ACTIVE後の参加）は不可で確定。将来的に変更する場合は別ストーリー。
