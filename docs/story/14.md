# 01-spec.md — US-14: 結果表示（面積・オブジェクト数・多角形）

> プレイヤーとして、結果（面積・有効/無効・オブジェクト数・多角形頂点）を取得・表示したい。勝敗とスコアを確認するため。
> 本仕様は1実装単位（US-14）分。Phase 2（実装）へ引き継ぐ。

US-13で保存・返却される結果を、参加者全員が確認できる画面にする。最終確定したプレイヤーは確定応答から、他の参加者と再訪した参加者は状態取得から、同じ結果を表示する。既存の合意仕様を正とし、現在の画面で結果が使われていない箇所を実装時に補う。

---

## 1. 合意された仕様

### 1.1 データ源（API 変更なし）

- データ源は US-08 の GET `result`（US-13 が COMPLETED 時に埋める）: `areaSqm` / `areaValid` / `objectCount` / `polygon`。
- **進行中は伏せていた `objectCount` をここで開示**する（スコア）。
- 地図に**最終多角形（`result.polygon`）**を描く。頂点はサーバー提供・クライアント非計算。
- 新しいAPI・DB変更は不要。US-13のconfirm応答とGETは同じGameResultPayload形式を使う。polygonは外周順の閉環であり、始点・回転方向は固定しない。
- US-15では同じ結果形式に獲得明細の `objects` を追加する。項目・保存・API契約は [US-15](15.md) を正とし、本USの結果遷移・保持の仕組みで結果全体を受け渡す。

### 1.2 結果画面への遷移（K1: 案A）

- **COMPLETED を検知したら自動で結果画面に遷移**する。
  - 確定した本人: N人目の confirm レスポンス（`result` 同梱・US-13）で即遷移。
  - 他プレイヤー: 2秒ポーリングで `status=COMPLETED` / `result` を検知して遷移。
- ゲーム終了＝全員が結果へ移るため、手動ボタンではなく自動遷移。
- 画面の切り替えは既存の `/game/<gameId>?p=<playerId>` 内で行い、結果専用URLは増やさない。再訪・再読み込みではGETから保存済み結果を表示し、参加API・confirm・集計を再実行しない。
- 参加者の確認はUS-05を維持する。playerIdなしの完了ゲームは「参加できません」、参加者一覧にないplayerIdは「ゲームが見つかりません」とし、結果画面より先に判定する。
- confirmが非nullのresultを返した場合、Smart側で結果を保持して即時表示する。次のGETの成功を待たず、遅れて到着したACTIVEの応答によって地図画面へ戻さない。保持する結果はgameId・playerIdに対応付け、別ゲーム・別プレイヤーへ持ち越さない。
- confirmのresult:nullは通常の非最終確定であり、結果画面への切り替えを起こさない。GETのCOMPLETEDでresult:nullの場合は異常系として扱う。

### 1.3 結果画面の構成（K2: 案A）

- 結果画面の上部に、緑のチェックマークと「位置情報のトラッキングを終了しました」を表示する。読み上げ可能な控えめな状態通知とし、結果の操作を遮らない。再訪時や結果データの異常表示でも追跡しない状態を案内する。GPS監視と定期的なライブ位置送信は、結果へ切り替える既存の後始末で終了する。
- 地図に**最終多角形＋各頂点**を描画（努力の成果物を見せる）。
- 「各頂点」は凸包の頂点を指す。閉環の末尾と先頭は同一点なので、頂点マーカーを重複表示しない。凸包の内側にいるプレイヤーの確定点や名前付き確定マーカーは、現在の結果APIに含まれないため追加しない。
- 地図は最終多角形全体が収まるように表示する。ライブ位置・暫定凸包・面積メーター・確定ボタンは結果画面に出さず、現在地を取得できない場合も結果の表示を妨げない。
- 数値表示: **面積（`areaSqm`・人間可読な単位）／スコア（`objectCount`）**。
- 面積の単位・桁区切りは既存の面積表示の規則を再利用する。結果画面では保存済みのareaSqmを使い、currentAreaから表示を作らない。
- 正常系は共通の完了表示とスコアを提示する。objectCountが0でも正常な完了として「0個」を表示する。獲得数に応じた評価・メッセージ・演出の段階分けは行わない（D1=A）。
- 獲得数は数値表示とし、獲得オブジェクトのマーカー・選択時の名前表示はUS-15で追加する。対象と表示の詳細はUS-15を正とする。

### 1.4 `areaValid=false` は異常系（K3: 改訂）

- **面積無効（上限超過・下限未満）は確定不能**（US-13）なので、**正常系で COMPLETED に無効面積で到達することはない**。
- US-13は候補の面積を一度だけ判定し、成立した結果だけを保存する。無効結果を保存して完了する分岐は設けない。したがって結果の **`areaValid=false` は異常系**（バグ・不整合）として扱う。通常の「失敗画面」は用意しない。
- `areaValid=false` を受け取った場合: 成功演出やスコアを出さず、「結果を取得できませんでした（想定外の状態）」の**異常系表示**にとどめ、詳細はログ/エラー報告に回す（ユーザーには最小限の告知）。
- `polygon` が欠落（null）している場合も同様に異常系として扱う（正常系では頂点が入る）。
- COMPLETEDなのにresultがない場合も同じ異常表示とし、待機画面へ戻したり、ライブ位置から結果を補完したりしない。表示できないpolygon（空の配列など）を地図へ渡さない。
- 異常表示にも新規ゲーム作成への導線を用意する。ログ・エラー報告は既存の仕組みの範囲とし、外部監視サービスは追加しない。

### 1.5 コンポーネント構成 / 再戦導線

「新しいゲームを作成」のリンクは、[US-25](25.md)の共通の主要操作の外観に揃える。リンクとしての遷移と保存済み結果の表示は本仕様を維持する。

- Smart（コンテナ）が `result` を受け取り、Dumb（地図・多角形・スコア表示）に props で渡すだけ。Dumb は API を知らない。
- 取得済みゲーム状態とconfirm応答の結果を、ゲーム画面を切り替えるSmartへ集約する。確定用hookが応答のresultを捨てずに通知し、結果の取得のためだけの重複GETは追加しない。
- 結果表示への切り替えで進行中の測位画面を終了し、GPS監視・ライブ位置の定期送信・確定操作を停止する。結果表示用の地図はGPSに依存させない。
- 機能専用のSmart・Dumbは `frontend/src/features/game-result/` にまとめる。共通化が必要な描画・面積整形は共有部品として扱い、結果画面からAPIを直接呼ぶDumbは作らない。
- 再戦は**新規ゲーム作成（US-04）に戻る導線**のみ用意（共有・リマッチ機能は MVP スコープ外）。

## 2. 受け入れ条件

- [ ] COMPLETED を検知すると自動で結果画面に遷移する（確定本人は confirm 応答、他は ポーリング）。
- [ ] 最終confirmの応答だけで結果画面が表示され、GETが遅延・失敗しても即時切り替えが妨げられない。遅れたACTIVE応答で戻らない。
- [ ] 非最終confirmのresult:nullでは進行中画面を維持する。
- [ ] 参加済みのURLへの再訪・再読み込みで保存済み結果が表示される。非参加者の既存の画面分岐を維持する。
- [ ] 地図に最終多角形（`result.polygon`）と頂点が描画される。
- [ ] 面積（人間可読）と `objectCount`（スコア）が表示される。
- [ ] objectCount=0も正常表示となり、個数による評価・称賛演出の段階分けがない。
- [ ] 結果の頂点マーカーは閉環の先頭・末尾で重複せず、地図に最終多角形全体が収まる。
- [ ] 進行中に伏せていた `objectCount` がここで開示される。
- [ ] 獲得数の数値表示を維持する。獲得明細のマーカー・名前表示はUS-15の受け入れ条件に従う。
- [ ] `areaValid=false` または `polygon` 欠落のときは、成功演出を出さず異常系表示になる（通常の失敗画面は無い）。
- [ ] COMPLETEDでresult:null、または表示できないpolygonでも異常表示になる。成功扱い・待機画面へのフォールバックをしない。
- [ ] 結果画面は位置情報の許可なしでも表示でき、GPS監視・ライブ位置送信・確定操作を継続しない。
- [ ] 結果画面から新規ゲーム作成へ戻る導線がある。
- [ ] 表示に必要な API 呼び出しは Smart からのみ行われる。
- [ ] クライアントは多角形・面積を計算しない（`result` を描くだけ）。

## 3. テスト観点

- **自動遷移**: `status=COMPLETED`／`result` 検知で結果画面に遷移（confirm 応答経路・ポーリング経路の両方、fake timer）。
- **応答の前後関係**: confirmで結果を受け取った後に、古いACTIVEのGETが届くケースを作る。GET待ちなしの表示と巻き戻り防止、別ゲームへの結果持ち越し防止を確認する。
- **再訪・アクセス分岐**: 完了済みゲームの直接表示・再読み込み、playerIdなし、不正なplayerId、不在ゲームの既存分岐を検証する。
- **描画**: `result.polygon` から多角形＋頂点が描かれる。面積・objectCount が正しく出る。
- **開示**: 進行中は非表示だった objectCount が結果で表示される（回帰: 進行中に出ていないこと）。
- **異常系**: `areaValid=false`／`polygon=null` で成功演出を出さず異常系表示になること。
- **境界・後始末**: 0個の正常表示、空polygonとCOMPLETEDのresult:null、閉環頂点の重複排除、GPS拒否でも結果表示、切り替え後のGPS監視と送信タイマーの終了を確認する。
- **Dumb 分離**: 結果コンポーネントが API を import しない。
- テスト名はtest_Action_Condition_Resultに従い、frontend/testsにsrcをミラーして配置する。バックエンド契約は変更せず既存テストを回帰確認し、前後両方の品質ゲートを通す。
- 実ブラウザで最終confirm・他プレイヤーのポーリング・再訪からの結果表示を確認する。390px程度の画面幅でも地図・スコア・再作成導線が使えることを検証する。

## 4. スコープ

### 含む

- COMPLETED 検知での結果画面自動遷移。
- 最終多角形＋頂点の地図描画、面積・objectCount（スコア）表示、objectCount 開示。
- `areaValid=false`／`polygon` 欠落の異常系ハンドリング。
- 新規ゲーム作成への導線。
- confirm応答の結果を画面へ渡す結線、完了表示の保持、測位・送信の終了、必要な共有描画・整形処理の整理。

### 含まない（他ストーリー / 将来）

- 集計・結果の生成（US-13 で対応済み。ここは表示のみ）。
- 獲得オブジェクトの情報取得・保存・API拡張・個別マーカーと名前表示の実装（US-15で担当）。
- 通常の「面積無効による失敗画面」（無効面積は確定不能なので正常系に存在しない）。
- 確定座標の上書き・やり直し（US-17・任意/将来）。
- 結果の共有・リマッチ機能。
- 正多角形スコア（`regularityPct` / `regularityValid`）の表示・称賛演出（追加要件レイヤー・MVP 完了後にフィールド追加＋表示追加）。
- クライアント側の多角形・面積計算（禁止）。
- 獲得数による評価基準・段階別の称賛演出（将来。今回のD1=Aで対象外とする）。
- 凸包内側のプレイヤーも含む全員の確定点・名前の表示、結果専用URL、非参加者向けの結果共有、外部エラー監視の導入。

### 前提

- COMPLETED 後の `result` は固定（再集計なし・US-13）。結果画面は何度開いても同じ。
- 正常系の結果は常に有効面積（成功）＋スコア。真の合否（pass/fail）は正多角形追加要件（将来）で `regularityValid` として加わる想定。
