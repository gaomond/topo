# 01-spec.md — US-13: 集計トランザクション（N人目の確定で結果を確定）

> システムとして、N人目の確定を引き金に同一Txで「凸包→測地面積→閾値判定→範囲内COUNT→保存→COMPLETED」を実行したい。結果を確定し改ざんを防ぐため。
> 本仕様は1実装単位（US-13）分。Phase 2（実装）へ引き継ぐ。

---

## 1. 合意された仕様

### 1.0 ルール前提（面積の上限と下限）

面積無効には2ケース（上限超過・下限未満）があるが、**どちらも「確定不能」**として扱う（J2/J3 改訂）。確定の時点で弾くため、**COMPLETED に無効面積で到達することはない**。

- **上限超過（`area > areaThreshold`）→ 確定不能**。その確定は受け付けない（記録しない）。近づいて縮めてから確定し直す。凸包は単調増加なので、**各確定でチェック**すれば面積は常に上限以下に保たれる。
- **下限未満（`area < areaMinThreshold`）→ 確定不能**。「面積0付近」は厳密なゼロ検出が難しいため、**下限閾値 `areaMinThreshold`（新規・アプリ定数）**で実用的に判定する。下限は最終形でのみ意味を持つため、**N人目（最終）確定でチェック**し、下限未満なら確定不能（散らばって面積を広げてから確定し直す）。
- したがって **正常系では COMPLETED 時の `area_valid` は常に true**。`area_valid=false` が結果に現れたら**異常系**（バグ・不整合）として扱う（US-14 で異常系ハンドリング）。`area_valid` カラムは防御的に保存する。
- `objectCount` は凸包内の対象数（正常系では常に成立しているので COUNT を実行）。

`areaMinThreshold` はアプリ定数（コード内・後から調整可能）。真の退化直上に低めに設定し、通常プレイで踏まないようにする（下限による確定不能を稀にする）。将来 config / プリセット別に持たせる余地は残す（本 US では単一定数）。

### 1.1 トリガと同一トランザクション（J1: 案A / J5: 案A）

confirm ユースケース（US-11）を拡張し、**各 confirm を同一 Tx で処理**する。

1. **`game` 行を `SELECT ... FOR UPDATE`（行ロック）**で取得（J5: 案A）。Nの判定〜集計〜遷移を直列化し、二重集計・二重 COMPLETED を防ぐ。
2. 状態・所属・座標の検証（US-11: ACTIVE のみ / 未確定 / `Coordinate` 範囲）。
3. **確定不能チェック（J2/J3 改訂）**: この確定点を含めた**確定済み fixed 点の凸包面積**を計算する。
   - **上限（毎確定）**: `area > areaThreshold` なら確定不能（記録せずロールバック。`422`、理由 `AREA_EXCEEDS_THRESHOLD`）。確定点が3点未満で多角形が成立しない間は面積0扱いで通過。
   - **下限（N人目＝最終確定のみ）**: この確定で `playerCount` に達する場合、最終面積が `area < areaMinThreshold` なら確定不能（`422`、理由 `AREA_BELOW_MIN`）。散らばって広げてから確定し直す。下限は途中の小さい面積では判定しない（面積は積み上がるため、最終形でのみ意味を持つ）。
4. 確定を記録（`fixed_geom` / `confirmed_at`。US-11）。
5. **確定数 == `playerCount` なら集計を実行**（1.2）。そうでなければ確定状態を返して終了。
6. コミット。

### 1.2 集計ステップ（同一 Tx 内）

全員の `fixed_geom` に対して、以下を1トランザクションで実行:

1. **凸包**: `ST_ConvexHull(ST_Collect(fixed_geom))`。
2. **測地面積**: `ST_Area(hull::geography)` で実 m²（学習メモ: 面積は `::geography`）。
3. **面積判定（防御的）**: `area_valid = (areaMinThreshold <= area <= areaThreshold)`。正常系では確定不能チェックにより常に true。false は異常系（保存はするが、通常は起きない）。
4. **範囲内 COUNT**（正常系では常に実行。万一 `area_valid=false` の異常系ならスキップして 0）:
   - `ST_Covers(hull, obj.geom)`（J4: 案B。境界上も含む・予測可能）で、かつ **`obj.object_type == game.object_type`** に一致する `game_object` を COUNT。
   - 内包判定は geometry のまま（学習メモ）。`game_object.geom` の GIST インデックス前提。
5. **保存**: `game` の結果カラム（US-00 で用意済み）に `polygon_geom`(Polygon,4326) / `area_sqm` / `area_valid` / `object_count` を書く。
6. **遷移**: `status = COMPLETED`。

### 1.3 結果の返却

- COMPLETED 後、`GET /api/games/{id}` は `result` を返す（表示は US-14）:
  ```json
  "result": {
    "areaSqm": 1500000,
    "areaValid": true,
    "objectCount": 12,
    "polygon": [{ "lat": 35.68, "lng": 139.76 }, ...]
  }
  ```
- N人目の confirm のレスポンス（US-11 H4）にも `result` を乗せ、確定操作の直後に結果を返せるようにする。

## 2. 受け入れ条件

- [ ] 各 confirm は `game` 行ロック下で処理され、二重集計・二重 COMPLETED が起きない。
- [ ] 凸包面積が `areaThreshold` を超える確定は **422（`AREA_EXCEEDS_THRESHOLD`）で拒否**され、記録されない（確定不能）。
- [ ] N人目（最終）確定で最終面積が `areaMinThreshold` 未満なら **422（`AREA_BELOW_MIN`）で拒否**され、記録されない（確定不能）。
- [ ] 確定不能で拒否されたプレイヤーは、位置を調整して再度確定できる（記録されていないため）。
- [ ] 確定点が3点未満の間は上限チェックを通過する（面積未成立）。下限は最終確定でのみ判定される。
- [ ] N人目の確定で同一 Tx に凸包→面積→判定→COUNT→保存→COMPLETED が実行される。
- [ ] 正常系では COMPLETED 時 `area_valid=true`（confirm が無効面積を弾くため）。`area_valid=false` は発生しない（発生したら異常系）。
- [ ] `object_type` 一致かつ凸包に `ST_Covers` される `game_object` が COUNT される。
- [ ] 結果（`polygon_geom` / `area_sqm` / `area_valid` / `object_count`）が保存され、GET / confirm レスポンスで `result` が返る。
- [ ] COMPLETED 後の confirm は 409（US-11 のガード）で再集計されない。

## 3. テスト観点

- **同一 Tx / 原子性**: 集計途中で例外時に確定記録ごとロールバックされること（部分反映なし）。COMPLETED と結果保存が同一 Tx。
- **行ロック / 競合**: 最後の確定が同時に来ても二重集計されない（並行テスト。`FOR UPDATE` で直列化）。
- **確定不能（上限）**: 上限を超える確定が 422（`AREA_EXCEEDS_THRESHOLD`）で拒否され記録されないこと。近づいて再確定すると成功。凸包単調増加で上限が常に保たれること。
- **確定不能（下限）**: N人目の最終確定で下限未満なら 422（`AREA_BELOW_MIN`）で拒否され記録されないこと。散らばって再確定すると成功。途中の小面積では下限判定しないこと。
- **正常系 areaValid**: 正常フローで COMPLETED 時 `area_valid=true` になること（`false` が出ないこと）。
- **COUNT（Level 3, Testcontainers 実 PostGIS）**: `ST_Covers` で境界上の点が含まれる。`object_type` フィルタが効く。範囲外オブジェクトが除外される。GIST インデックス利用。
- **測地面積**: `ST_Area(::geography)` が実 m² を返す（既知形状で検証）。
- **保存 / 返却**: 結果4カラムが入り、GET / confirm の `result` に反映。退化で `polygon_geom=NULL` を吸収。

## 4. スコープ

### 含む

- confirm 拡張: `game` 行ロック・確定不能チェック（上限超過→422 / 最終確定の下限未満→422）・N人目トリガでの同一 Tx 集計。
- 集計: 凸包・測地面積・面積判定（防御的・正常系は常に成立）・範囲内 COUNT（`ST_Covers`＋`object_type` 一致）・結果保存・COMPLETED。
- `areaMinThreshold`（下限閾値）のアプリ定数導入と下限確定不能判定。
- 結果の GET / confirm レスポンス返却（`result`）。

### 含まない（他ストーリー / 将来）

- 結果画面の表示・演出（US-14）。
- 確定座標の上書き（US-17・任意/将来）。
- 退化ケースの詳細セマンティクスの最終確定（US-16・任意）。本 US は下限閾値で実用的に無効化する既定を採る。
- 正多角形スコア（`regularity_pct` / `regularityValid`）の確定時計算（追加要件レイヤー・MVP 完了後。同一 Tx に相乗りさせる想定）。
- 範囲内オブジェクトの一覧取得・地図可視化（US-15・任意）。
- `areaMinThreshold` の config / プリセット別化（本 US は単一定数）。

### 判断ログ（3 Amigos）

| # | 論点 | 判断 | 理由 |
|---|---|---|---|
| J1 | 集計トリガ | 案A: confirm ユースケース内で同一 Tx 同期集計 | 同一Tx・改ざん防止がストーリーの核 |
| J2 | 上限超過の扱い | **改訂: 確定不能（422 `AREA_EXCEEDS_THRESHOLD`・記録しない）**。毎確定チェック | 上限は超えてはいけない線。失格化せず確定を弾く。凸包単調増加で毎確定チェックすれば常に上限以下 |
| J3 | 下限（面積0付近）の扱い | **改訂: 下限閾値 `areaMinThreshold` 未満も確定不能（422 `AREA_BELOW_MIN`）**。最終確定でチェック | 面積0は厳密に作りにくく下限で実用判定。無効面積では確定させない（両側とも確定不能）ので、結果の `area_valid=false` は異常系 |
| J4 | 範囲内 COUNT の述語 | 案B: `ST_Covers`（境界上も含む） | 境界の取りこぼしを避け予測可能。GIST 前提で高速 |
| J5 | 同時確定の制御 | 案A: `game` 行ロック（`SELECT ... FOR UPDATE`） | Nの判定〜集計〜遷移を直列化し二重発火を防ぐ |

### 前提

- 行ロック保持中の集計は N=3・GIST で絞れる規模なら短時間。大規模データは COUNT のインデックス最適化が要る（`game_object.geom` の GIST を US-01 投入で用意）。
- `areaThreshold`（上限）はプリセット由来（作成時確定）。`areaMinThreshold`（下限）はアプリ定数。
- 確定不能の HTTP コードは 422（理由 `AREA_EXCEEDS_THRESHOLD` / `AREA_BELOW_MIN`）を採用。状態競合の 409 とは別種の「ルール違反」として区別（クライアントが専用メッセージを出せる）。
- **下限のソフトロック懸念**: N-1人が極端に密集/一直線だと、N人目がどこで確定しても下限に届かない可能性がある。`areaMinThreshold` を真の退化直上に低く設定して通常プレイで踏まないようにする。恒久対策（上書き＝US-17、退化セマンティクス＝US-16）は別途。
- 確定点・凸包・面積・COUNT はすべて 4326。正多角形（将来）は EPSG:3857 に変換して判定する想定（保存は 4326）。
