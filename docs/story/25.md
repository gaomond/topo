# 01-spec.md — US-25: 作成・待機画面のUIと主要操作の統一

実装・検証・独立レビュー承認済み（2026-11-10）。

> プレイヤーとして、ゲームの作成・参加・開始を分かりやすい画面で操作したい。待機が続いていることを把握し、仲間への招待と次の操作を迷わず行うため。
> 本仕様は1実装単位（US-25）分。Phase 2（実装）へ引き継ぐ。

作成・参加フォームは項目と操作の境界が乏しく、待機画面は静止して見える。招待URLとコピー操作が離れ、主要ボタンの色も画面ごとに異なる。共通のUI部品で外観と操作状態を揃え、作成からプレイまで次の操作が分かるようにする。

```text
作成フォームで面積カードを選ぶ → 共通の主要ボタンで作成
  → 「待機中…」と参加者一覧 → URL横のアイコンで招待URLをコピー
  → 定員が揃った作成者が開始 → プレイ中の確定も同じ主要ボタンの外観
```

## 1. 合意された仕様

### 1.1 UI部品と役割（D1=A、D2=A）

- 既存のReact 19・Tailwind CSS v4を維持し、shadcn/uiの必要な部品だけを導入する。共有する表示部品は `frontend/src/shared/` 配下に置く。部品名・実装元・配置は計画時に具体化し、生成例のフォルダ構成で既存の機能別配置を崩さない。
- 共通のButtonに主要・補助・アイコンの外観と、hover・押下・フォーカス・無効・送信中の規則を定める。各画面で色を再定義しない。リンクはリンクの意味を維持して同じ主要操作の外観を使う。
- 主要操作は「ゲームを作成」「参加する」「ゲームを開始」「この位置で確定」「確定する」、結果画面の「新しいゲームを作成」、説明の「次へ」「探検を始める」を青で揃える。既存の再試行ボタンにも同じ規則を適用する。
- キャンセル・戻るは淡い面と枠線、コピー・閉じる・スキップなどは控えめな外観にする。主要操作との優先度が分かるようにし、色以外にも塗り・枠・文言で区別する。
- 画面の幅や操作の役割によってボタンの幅は変えてよい。タップ領域は原則44px以上とし、アイコンだけのボタンにも操作名とフォーカス表示を付ける。Leaflet標準コントロールの置き換えは行わない。
- フォームの状態・API・ポーリングは既存のSmartが担う。表示部品へAPI処理を移さず、新しいフォーム管理ライブラリやダイアログ基盤の全面置換は追加しない。

### 1.2 見た目の方向

利用者の参考画像から、淡い空・草地の色、遠くへ続く街の広がり、日常のものの縮尺が少しずれるシュールさを取り入れる。色数と装飾を抑え、あたたかい背景・余白・丸みで柔らかさを出す。

| 役割 | 基準色 | 用途 |
| --- | --- | --- |
| 背景 | `#F7F5EE` | あたたかい生成り色の画面背景 |
| 面 | `#FFFEFA` | フォーム・説明・入力欄 |
| 主要操作 | `#356477` | 落ち着いた青。白文字の主要ボタンと選択枠 |
| 空の淡色 | `#E8F0F3` | 選択カードや補助面 |
| 草地・差し色 | `#E7EFDF` / `#F3DFD0` | 小さな補助面。操作の優先度を曖昧にするほど広く使わない |
| 文字 | `#263F45` / `#536C72` | 本文・補助説明。淡い背景でも読み取れる濃さを保つ |

- 角丸は入力・ボタンで12〜16px程度、まとまった面で20〜24px程度を基準とする。影は薄くし、強い光沢・多色のグラデーション・多量の装飾は加えない。通常文字と背景はコントラスト比4.5:1以上を維持する。
- 待機画面の採用済み惑星画像・説明内容はUS-19を維持する。今回の世界観は主に配色と余白で表し、新しいイラスト、参考作品のロゴ・キャラクター・画面の転用は含めない。
- [配色と部品の見本](../design/us25-ui-direction.png)は静的な方向見本であり、配置・文言・動作の契約は本書と各機能の既存仕様を正とする。微調整は実装時に可能とする。

### 1.3 トップ画面の構成とコピー（D4=A）

- トップ画面は既存のゲーム作成画面（`/`）とする。紹介と作成フォームを同じページに置き、別のランディングページや「作成へ進む」ためだけの遷移は追加しない。
- キャッチコピーは **「歩いて、囲んで、街を再発見。」** とする。説明文も文の区切りに句点を使う。句点を使わないという一律の表記規則は設けない。
- 補助説明は次の文言とする。画面幅に合わせて折り返し、地物の意味も併記する。

  > 仲間と歩いて、それぞれの位置を確定。
  > みんなで囲んだ範囲に、いくつの地物があるか見つけよう！

  「地物」は建物や施設などのことだと分かる短い説明を添える。ゲーム全体の説明にはこの用語を使い、特定の対象種別だけを扱うように書かない。
- 通常幅は左にコピー・補助説明・既存の惑星画像、右に作成フォームを配置する。スマートフォンではコピー・説明・フォームの1列を基本とし、図は小さく添えて作成操作を過度に下へ押し下げない。
- [トップ画面の見本](../design/us25-top-direction.png)を配置の基準とする。見本の文言や入力値は本書と既存API契約に従い、実装時に実データと接続する。

### 1.4 作成・参加フォーム（D3=A）

- ページの幅を抑え、見出し・項目・補助説明・主要ボタンを縦方向に整理する。390px幅では1列を基本とし、通常幅でも項目が散らばらないようにする。
- 作成フォームの対象種別・人数・任意の表示名を維持する。人数は現行どおり初期値3・最小3の編集可能な入力とする。対象は設定APIの選択肢を使い、既知の種別は「神社」などの表示名にする。送信値は既存の識別子を維持する。
- 面積プリセットは単一選択のカードにする。設定APIが返す順序・label・sqmから、名前と上限面積を表示し、既存のkeyを送る。選択は初期値・キーボード・タップのいずれでも1件に保ち、選択中を枠とラジオ表示で示す。値をフロントへ複製しない。
- 面積の単位・数値整形は既存の `formatArea` に揃える。選択カードの面積は上限であり、目標や必須の面積とは説明しない。
- 参加画面も同じ入力欄と主要ボタンを使う。表示名省略時の扱い、送信中の二重操作防止、失敗時の入力保持・エラーは既存契約を維持する。設定取得中・取得失敗の表示も同じ背景・余白へ揃える。

### 1.5 待機画面とコピー操作

- 見出しを「待機中…」にし、固定幅の3点を順に明滅させる。点の変化でレイアウトを動かさない。読み上げでは静的な「待機中」を伝え、点は繰り返し通知しない。`prefers-reduced-motion: reduce` では点を静止させる。
- 点は待機状態の継続を表し、各GETの実行・成功とは結び付けない。既存の2秒ポーリングとエラー処理を維持し、装飾のための通信を追加しない。状態は日本語の見出しで伝え、生の `状態: WAITING` の重複表示は外す。
- 参加者一覧、人数、目的説明・画像、開始ボタンを読み進められるまとまりにする。開始ボタンは全員に表示し、作成者・定員・送信中による活性条件はUS-06を維持する。
- 招待URLのすぐ横に、操作名「招待URLをコピー」を持つアイコンボタンを置く。長いURLは表示領域内で省略・折り返ししてよいが、実際にコピーする値は既存の招待URL全文とする。短縮URL機能は追加しない。
- 成功時はチェックと「コピーしました」を2秒表示し、通常のアイコンへ戻す。成功後もボタンを無効化せず繰り返しコピーできる。連続して成功した場合は最後の成功から2秒とする。
- 失敗時は成功表示を出さず、「コピーできませんでした。URLを選択してコピーしてください」と表示する。URLは手動で選択・コピーでき、ボタンでも再試行できる。状態通知は読み上げでも確認できるようにする。
- フィードバックは現在の招待URLに対応させ、別ゲームへの移動や離脱後に旧コピーの応答・タイマーが表示を書き換えないようにする。

### 1.6 既存契約との境界

作成・参加・開始・確定・結果のAPI、Domain・UseCase・ポート、DBスキーマは変更しない。US-21の参加後の読み込みとGETだけの再試行、US-11の不可逆な確定の確認、US-14の完了結果保持、US-19の説明と測位開始順を維持する。

共通テーマの追加で、地図上の帰属表示・GPS・面積メーター・ライセンス案内の操作を妨げない。追加する依存物は、US-22の既存のライセンス生成経路でも確認する。収集範囲の契約はUS-22から拡張しない。

## 3. テスト観点

テスト名は `test_Action_Condition_Result` とし、実ソースを対象に `frontend/tests/` へ配置する。

- **フォーム・共通部品** — 設定値を変えてもカード表示・順序・選択・送信値が一致する。名前省略・人数入力、送信中・失敗後の既存動作、リンクの遷移とボタンの操作を検証する。
- **コピー** — Clipboardを注入し、全文、複数回成功、最後の成功からの2秒、失敗と復旧、別URL・アンマウント後の遅延応答を確認する。時間制御はfake timerを使う。
- **結線の回帰** — 開始条件と参加後の取得待ち・失敗・再試行、確定の確認・キャンセル・送信中、結果と説明の遷移を確認する。見た目の変更だけで新しいPOSTやGETが発生しない。
- **実ブラウザ** — 通常幅と390px幅、主要・補助・フォーカス・無効の外観、カードのキーボード選択、コピーと成功通知を確認する。動く点と動きを減らす設定、実Joyrideの強調・フォーカス、既存dialog・地図の帰属表示も確認する。CSS文字列の一致だけで外観確認を代用しない。
- **バックエンド** — 契約変更がないため新しいDomain・UseCase・Adapterのテストは追加しない。既存のバックエンドとフロントの品質ゲートを通す。
