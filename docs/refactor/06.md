# RS-06 — 保存ポートのドメインモデルへの統一

> 開発者として、Game・Player の保存ポートを、ドメインモデルを受け取る契約に揃えたい。UseCase が操作したモデルを Repository に渡し、永続化表現への変換と保存を Repository の責務として完結させるため。RS-00 の構成統一後に実施する。（US-04、US-05、US-06、US-07）

[リファクタ一覧](REFACTOR.md) に登録した計画。詳細仕様・受け入れ条件は、実装前の 3 Amigos で確定する。

| 対象 | 変更内容 |
| --- | --- |
| ドメインモデル | 作成・更新で保存する情報と、モデルが責任を持つ状態の範囲を整理する。現在の `Game` にない保存項目や Player のモデル化も検討する。 |
| 保存ポート・UseCase | 個別の値を渡す保存契約から、ドメインモデルを受け取る契約へ移行する。モデルの操作後に UseCase が保存を依頼する流れに揃える。 |
| Repository の実装 | ドメインモデルから `XxxRecord` への変換と、新規作成・更新の扱いを定める。モデルに含めない既存の保存値や空間カラムを失わないようにする。 |
| 回帰確認 | API・DB スキーマ・ゲーム作成時の保存順序・更新対象外のカラムと、RS-05 のロックおよびトランザクションによる整合性を維持する。 |

具体的な保存メソッド名、モデルが保持する項目、ライブ位置などの部分更新をモデルの保存としてどう表すかは、RS-06 の詳細化で確定する。ゲーム生成時の業務ルールの配置は RS-04 と整合させる。

## RS-04で確定した分担

[RS-04](04.md) で、ゲーム作成に必要なGame・Playerモデルと、モデルを受け取る既存Repositoryの作成契約を先に整える。作成専用ポート・Adapterは追加せず、ゲーム保存・作成者保存・紐付けの順序とトランザクションはUseCaseが管理する。本チケットはその契約を再設計せず、開始・ライブ位置などに残る保存契約の統一を扱う。共有する作成契約を使う参加処理の追従はRS-04に含め、参加固有の追加整理は本チケットの詳細化で判断する。
