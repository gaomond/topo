# RS-07 — コメント・KDoc と命名の整理

> 開発者として、既存バックエンドのコメント・KDoc を、コードだけでは伝わらない理由・制約・契約に絞りたい。実装を読み上げる説明や規約の重複、古い説明を減らし、変更時に必要な根拠を見つけやすくするため。

[リファクタ一覧](REFACTOR.md) に登録した計画。詳細仕様・受け入れ条件は、実装前の 3 Amigos で確定する。

[AGENTS.md](../../AGENTS.md) に整備済みのコメント・KDoc 方針と命名規則に、既存コードを揃える。必要な補足も AGENTS.md に反映する。

| 対象 | 変更内容 |
| --- | --- |
| コメント・KDoc | コードの読み上げ、DIP など共通規約の繰り返し、一時的な作業状況を削減する。古い型名・引数・戻り値・例外や参照を修正する。 |
| 残す説明 | 判定順の理由、ロックで守る条件、SQL・外部仕様の制約、公開する操作の契約を残す。必要な判断の経緯は仕様書へ参照を付ける。 |
| 命名 | コメントで補足している内容を名前で表せるか確認し、AGENTS.md の命名方針に揃える。`Game.requireCanJoin`・`Game.start` の人数参照関数の改名は RS-00 で対応済み。 |
| REST との対応 | Controller から UseCase を追える参照を整え、UseCase に URL・HTTP ステータスの対応を重複記載しない。OpenAPI の導入は RS-08 で行う。 |

業務ルール、判定順、人数を参照するタイミング、API、行ロックとトランザクションは維持する。
