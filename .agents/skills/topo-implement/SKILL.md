# topo-implement

対象は確定済みの1ストーリー。指定された仕様パスを使う。US番号だけなら
`docs/story/<NN>.md`、省略時は `.agent-pipeline/01-spec.md` を使う。
仕様が見つからない、または未合意なら、実装前に topo-spec で解決する。

1. `AGENTS.md`、`docs/DESIGN.md`、対象仕様を確認する。作業ツリーに既存の変更があれば、対象の差分を区別できるよう開始時の状態を把握する。
2. `pipeline-plan` を起動し、対象仕様のパスを渡す。`.agent-pipeline/02-plan.md` を確認して次に進む。
3. `pipeline-impl` を起動し、対象仕様と計画を渡す。差し戻しのときだけ、今回の `05-review.md` も渡す。実装とテストの記録を確認する。
4. 品質ゲートが成功したことを確認する。実行担当の報告またはフック結果で確認できない場合は `bash scripts/quality-gate.sh` を実行する。失敗中はレビューに進まず、原因を実装担当に戻す。
5. 新しい `pipeline-review` を起動し、対象仕様・実装メモ・今回の差分の範囲を渡す。レビュー担当は判定と指摘を返す。オーケストレーターが結果を `.agent-pipeline/05-review.md` に保存する。
6. 判定が「要修正」なら手順3に戻る。初回を含め実装は最大3回。承認に至らなければ残る指摘を報告する。
7. 承認後、`pipeline-finish` を起動して `.agent-pipeline/06-commit-ready.md` を作る。最終状態とコミットメッセージ案を報告する。自動コミットはしない。

各段階は別のサブエージェントを使って直列に進める。オーケストレーターはソースを書かず、前段が終了して成果物を確認してから次を起動する。前回の成果物は今回の完了判定に使わない。
